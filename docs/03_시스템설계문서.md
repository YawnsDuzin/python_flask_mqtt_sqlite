# 시스템 설계 문서

## 1. 시스템 개요

### 1.1 목적
IoT 센서에서 발행되는 MQTT 메시지를 수신하여 파싱, 저장, 가공 후
재발행하는 웹 기반 데이터 수집/중계 시스템

### 1.2 주요 기능
- 다중 MQTT 토픽 구독 및 메시지 수신
- 센서 타입별 데이터 파싱
- SQLite 데이터베이스 저장
- 가공/집계 데이터 MQTT 재발행
- 웹 대시보드를 통한 실시간 모니터링

### 3.2 테이블 생성 SQL
```sql
-- sensors 테이블
CREATE TABLE IF NOT EXISTS sensors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sensor_id VARCHAR(50) UNIQUE NOT NULL,
    sensor_type VARCHAR(30) NOT NULL,
    location VARCHAR(100),
    description TEXT,
    is_active BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- sensor_data 테이블
CREATE TABLE IF NOT EXISTS sensor_data (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sensor_id VARCHAR(50) NOT NULL,
    sensor_type VARCHAR(30) NOT NULL,
    value REAL NOT NULL,
    unit VARCHAR(20) NOT NULL,
    raw_payload TEXT,
    topic VARCHAR(200),
    qos INTEGER DEFAULT 0,
    timestamp DATETIME,
    received_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sensor_id) REFERENCES sensors(sensor_id)
);

-- 인덱스 생성
CREATE INDEX IF NOT EXISTS idx_sensor_data_sensor_id ON sensor_data(sensor_id);
CREATE INDEX IF NOT EXISTS idx_sensor_data_timestamp ON sensor_data(timestamp);
CREATE INDEX IF NOT EXISTS idx_sensor_data_received_at ON sensor_data(received_at);
CREATE INDEX IF NOT EXISTS idx_sensor_data_type ON sensor_data(sensor_type);

-- processed_data 테이블
CREATE TABLE IF NOT EXISTS processed_data (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sensor_id VARCHAR(50) NOT NULL,
    process_type VARCHAR(30) NOT NULL,
    value REAL NOT NULL,
    period_start DATETIME,
    period_end DATETIME,
    sample_count INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sensor_id) REFERENCES sensors(sensor_id)
);

-- mqtt_logs 테이블
CREATE TABLE IF NOT EXISTS mqtt_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_type VARCHAR(20) NOT NULL,
    topic VARCHAR(200),
    message TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 6. API 설계

### 6.1 REST API 엔드포인트

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/sensors` | 모든 센서 목록 조회 |
| GET | `/api/sensors/<sensor_id>` | 특정 센서 정보 조회 |
| GET | `/api/sensors/<sensor_id>/data` | 센서 데이터 조회 (with 필터) |
| GET | `/api/data/latest` | 최신 데이터 조회 |
| GET | `/api/data/stats` | 통계 데이터 조회 |
| POST | `/api/mqtt/publish` | MQTT 메시지 발행 |
| GET | `/api/health` | 시스템 상태 확인 |

### 6.2 API 응답 형식
```json
{
    "success": true,
    "data": { ... },
    "message": "Success",
    "timestamp": "2025-01-15T10:30:00Z"
}
```

### 6.3 웹 페이지 라우트

| Route | Description |
|-------|-------------|
| `/` | 메인 대시보드 |
| `/sensors` | 센서 목록 페이지 |
| `/sensors/<sensor_id>` | 센서 상세 페이지 |

## 7. MQTT 토픽 구조

### 7.1 수신 토픽 (Subscribe)
```
sensors/{sensor_type}/{sensor_id}

예시:
sensors/temperature/TEMP_001
sensors/humidity/HUM_001
sensors/vibration/VIB_001
sensors/+/+              # 모든 센서 구독
sensors/#                # 하위 모든 토픽 구독
```

### 7.2 발행 토픽 (Publish)
```
processed/{sensor_id}/{metric_type}

예시:
processed/TEMP_001/average
processed/TEMP_001/min
processed/TEMP_001/max
processed/TEMP_001/status

alerts/{sensor_id}
alerts/TEMP_001          # 임계값 초과 알림
```

## 8. 에러 처리 전략

- 웹 대시보드에 연결 상태 표시

### 8.2 데이터 파싱 오류
- 오류 로깅 (원본 데이터 포함)
- 기본 파서로 폴백
- 파싱 실패 통계 수집

### 8.3 데이터베이스 오류
- 트랜잭션 롤백
- 재시도 로직
- 오류 알림
